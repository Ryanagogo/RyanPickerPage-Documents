# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Docusaurus 3.10 documentation site for the **Ryan Picker Page** Unreal Engine plugin (an
animation picker for Control Rig). This repo holds **only the docs** — the plugin source is
not here, so plugin behaviour can only be confirmed from the existing prose, not the code.
Deploys to GitHub Pages under `baseUrl` `/RyanPickerPage-Documents/`.

## Commands

- `npm start` — dev server with hot reload at localhost:3000
- `npm run build` — static production build. **This is the check that matters**: run it
  after any docs change. `onBrokenLinks: 'throw'` in `docusaurus.config.js` makes a broken
  internal link or reference fail the build.
- `npm run serve` — serve the `build/` output (verify the built site)
- `npm run clear` — clear the `.docusaurus` cache when the dev server behaves oddly

Node >= 20 required. There are no tests and no linter.

## Publishing

Deploy = push to `main`; `.github/workflows/deploy.yml` runs `npm ci && npm run build` and
publishes to GitHub Pages.

- `/publish-docs` (**Plan Mode required** — a project hook enforces it) runs the full
  pre-flight (`node .claude/scripts/check-docs.mjs` + `npm run build`), converts/fixes what's
  flagged, then — after `ExitPlanMode` approval — commits `docs/` + `sidebars.js` +
  `static/img/` to `main`, pushes, and watches the Pages deploy, reporting success or the
  failing step.
- `node .claude/scripts/check-docs.mjs` on its own is the fast pre-flight: it lists sidebar
  ids with no file (build-breaking), non-MDX-clean docs, and **docs missing from
  `sidebars.js`**. Exit 1 if anything is build-breaking.

## Adding or editing a doc page

1. Docs are Markdown/MDX files in `docs/`. Files may be `.md` but use JSX (`<img .../>`,
   `import` lines) — Docusaurus MDX processes them.
2. **The sidebar is hand-maintained in `sidebars.js`** (not autogenerated). A new page does
   not show up until its file id (filename without extension) is added to the
   `tutorialSidebar` array in the right category.
3. Internal links use relative doc paths without extension: `[text](./getting-started)`,
   `[text](./save-load-and-files#session-state)`. A wrong path fails `npm run build`.
4. Some pages set `sidebar_position` in frontmatter; ordering within a category otherwise
   follows `sidebars.js`.

## Images

- Store images under `static/img/quick-start/<page-slug>/<name>.png` (this subfolder
  layout is the current convention; older flat paths are being migrated into it).
- Reference them with `useBaseUrl` so `baseUrl` is respected:

  ```jsx
  import useBaseUrl from '@docusaurus/useBaseUrl';

  <img src={useBaseUrl('/img/quick-start/<page-slug>/<name>.png')} alt="<name>" style={{display: 'block', marginLeft: 0, marginRight: 'auto'}} />
  ```

  Keep each `<img>` on one line — the Typora⇄Docusaurus converter normalises multi-line
  tags to a single line.

- Do **not** copy the raw `<img src="../static/img/...">` form seen in some older
  `quick-start-*` files — that is the Typora form (see below), not the Docusaurus form.

## Typora ⇄ Docusaurus conversion

The docs are authored in Typora, whose Markdown diverges from Docusaurus MDX. A converter
handles the round trip:

- `/convert-to-docusaurus` (alias `/ctd`) — Typora → Docusaurus MDX
- `/convert-to-typora` (alias `/ctt`) — Docusaurus → Typora

Both take doc names/paths or `all`, e.g. `/ctd quick-start-editor-basics` or `/ctd all`.
They wrap `node .claude/scripts/convert-md.mjs --to <docusaurus|typora> [names|--all] [--check]`
(run `--selftest` to sanity-check the script). It is deterministic and idempotent, and never
touches YAML frontmatter, fenced code blocks, or inline `code`.

What it converts: the `import useBaseUrl …` line (added/removed); `<img>` `src`
(`../static/img/…` ⇄ `useBaseUrl('/img/…')`) and `style` (HTML string ⇄ JSX object);
admonitions (`:::note`) ⇄ GFM alert blockquotes (`> [!NOTE]`); and MDX-hostile bare `{ }` /
`<` in prose. A leading UTF-8 BOM (Typora writes one) is preserved at byte 0. Constructs it
can't safely convert are reported as `needs-review` and left untouched.

Going to Docusaurus only, `/ctd` also recognises the absolute filesystem path Typora writes
into `src` once you've moved a pasted image into `static/img/…` (backslashes and all), and
overwrites `alt` to that file's name — no more hand-fixing either one. An absolute path that
isn't under this repo's `static/img/` (e.g. still sitting in Typora's own paste-cache folder)
is reported as `needs-review` instead of silently left as a dead link.

  before assuming its structure is final.
