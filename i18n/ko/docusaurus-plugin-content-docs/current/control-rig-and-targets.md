# Control Rig 및 대상 액터 \{#control-rig--target-actors}

*위젯이 무엇에 "연결"되어 있는지, 그리고 그 연결이 세션, 시퀀스, 리스폰을 어떻게 견디는지에 대한 설명입니다.*

위젯은 절대 하드 오브젝트 레퍼런스를 보유하지 않습니다. **이름과 식별자**(Control Rig
컨트롤 이름, 액터 식별자)를 저장하고, 클릭하는 순간 현재 에디터 상태를 기준으로 이를 해석합니다.
이러한 간접 참조 덕분에 저장된 페이지 하나가 에디터 재시작, 다른 레벨,
Sequencer의 액터 수명 주기 전반에서 계속 작동합니다.

## 현재 Control Rig \{#the-current-control-rig}

각 페이지 탭에는 헤더 드롭다운에서 선택하는 **현재 Control Rig**가 하나 있습니다. 드롭다운은
**포커스된 Level Sequence**에 바인딩된 리그를 나열하며 스스로 갱신됩니다. 피커가 열린 상태에서 다른
시퀀스로 전환하면 목록이 다시 만들어지는데, 선택한 리그가 여전히 바인딩되어 있으면 선택이 유지되고,
사용 가능한 리그가 하나뿐이면 자동으로 선택됩니다.

위젯의 컨트롤 이름은 이 리그를 기준으로 해석됩니다. 따라서 같은 페이지로 리그의 컨트롤 명명 규칙을
공유하는 모든 캐릭터를 조작할 수 있습니다. 이족 보행 페이지 하나를 만들어 전체 캐스트에 사용하세요.
([라벨](./widget-label)에 현재 리그 이름을 표시하면 애니메이터가 탭이 어떤 캐릭터를
조작하는지 항상 알 수 있습니다.)

## 대상 액터 \{#target-actors}

위젯은 리그 컨트롤 대신 또는 함께 **액터**를 대상으로 지정할 수도 있습니다. 버튼 하나로
소품, 카메라, 리그 컨트롤을 함께 선택할 수 있고, 슬라이더로 액터의 트랜스폼 채널을 직접 조작하며
손으로 만든 애니메이션처럼 Sequencer에 자동 키를 생성할 수 있습니다.

### Sequencer 스포너블 \{#sequencer-spawnables}

일반 레벨 액터는 안정적인 액터 GUID로 식별됩니다. **함정은 스포너블입니다**.
Sequencer는 세션마다 *새로운* 액터 GUID로 스포너블을 리스폰하므로, 이전 GUID로 저장된
페이지는 모르는 사이에 망가질 수 있습니다. 그래서 모든 위젯의 모든 액터 지정에는 두 가지 식별자가
나란히 저장됩니다. 액터 GUID*와*, 리스폰 간에도 안정적인 액터의 Sequencer
**바인딩 GUID**입니다. 해석 시에는 액터 GUID를 먼저 시도하고, 실패하면 바인딩으로 대체합니다. 이를
직접 관리할 필요는 전혀 없으며, 스포너블이 많은 페이지가 다음 주에도 작동하는 이유가 바로 이것입니다.

## 대상이 지정되는 방식 \{#how-targets-get-assigned}

편집 모드에서 위젯을 선택한 상태로:

- **생성 시 채우기**(기본값, [구성 가능](./editor-settings)): 새 위젯의 대상 목록은
  추가하는 시점에 선택된 컨트롤/액터로 미리 채워집니다. 뷰포트에서 선택 →
  Add Widget, 이것이 작성 과정의 전부입니다.
- 속성 편집기의 대상 필드는 해석된, 읽기 쉬운 요약(GUID가 아닌 실제 액터 및
  컨트롤 이름)을 보여 주므로 연결을 한눈에 확인할 수 있습니다. 깨진 레퍼런스
  (삭제된 액터, 이름이 바뀐 컨트롤)는 페이지에 오류를 일으키지 않고 그냥 아무것도 가리키지 않게 됩니다.

## 두 가지 선택 방식 \{#two-selection-philosophies}

[선택 버튼](./widget-select-button)은 피커의 고전적인 두 가지 동작을 모두 제공합니다.
**선택 세트**(클릭하면 선택이 저장된 세트로 바뀜)와 **대화형 선택 모드**
(버튼이 에디터 선택을 계속 반영하고 클릭은 선택에 추가됨. 전체 동작은 선택 버튼 페이지 참조)입니다.
선택 수집은 의도적으로 리그와 무관하게 동작합니다. 생성 시 채우기와 대화형 매칭은 드롭다운의 현재 리그에
속한 컨트롤뿐 아니라 에디터에서의 실제 선택 전체를 고려합니다.
