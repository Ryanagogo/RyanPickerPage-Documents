# Control Rig とターゲットアクター \{#control-rig--target-actors}

*ウィジェットが何に「接続」されているか、そしてその接続がセッション、シーケンス、再スポーンをどう乗り越えるか。*

ウィジェットはオブジェクトへのハード参照を保持しません。保存するのは **名前と識別子**（Control Rig の
コントロール名、アクターの識別子）で、クリックした瞬間にエディタの現在の状態に対して解決します。
この間接参照のおかげで、保存した 1 つのページがエディタの再起動、異なるレベル、
Sequencer のアクターのライフサイクルをまたいで動作し続けます。

## 現在の Control Rig \{#the-current-control-rig}

各ページタブには、ヘッダーのドロップダウンで選択する **現在の Control Rig** が 1 つあります。ドロップダウンには
**フォーカスされている Level Sequence** にバインドされたリグが一覧表示され、自動的に更新されます。ピッカーを開いたまま
別のシーケンスに切り替えるとリストが再構築されます。選択していたリグがまだバインドされていれば選択はそのまま保たれ、
利用可能なリグが 1 つだけなら自動的に選択されます。

ウィジェットのコントロール名はこのリグに対して解決されます。そのため、同じページでリグのコントロール命名を
共有するどのキャラクターも操作できます。二足歩行用のページを 1 つ作れば、すべてのキャストに使えます。
（[ラベル](./widget-label) に現在のリグ名を表示させれば、アニメーターはタブがどのキャラクターを
操作しているか常に把握できます。）

## ターゲットアクター \{#target-actors}

ウィジェットは、リグのコントロールの代わりに、またはそれに加えて、**アクター** をターゲットにすることもできます。1 つのボタンで
小道具、カメラ、リグのコントロールをまとめて選択できますし、スライダーでアクターのトランスフォームチャンネルを直接操作し、
手付けアニメーションと同様に Sequencer にオートキーを打つこともできます。

### Sequencer のスポーナブル \{#sequencer-spawnables}

通常のレベルアクターは安定したアクター GUID で識別されます。**落とし穴はスポーナブルです**。
Sequencer はセッションごとに*新しい*アクター GUID でスポーナブルを再スポーンするため、古い GUID で保存したページは
気づかないうちに壊れてしまいます。そこで、すべてのウィジェットのすべてのアクター割り当てには、2 つの識別子が
並行して保存されます。アクター GUID *と*、再スポーンをまたいでも安定している Sequencer の
**バインディング GUID** です。解決時はまずアクター GUID を試し、だめならバインディングにフォールバックします。これを
管理する必要は一切ありません。スポーナブルを多用するページが翌週も動作するのはこのためです。

## ターゲットの割り当て方法 \{#how-targets-get-assigned}

編集モードでウィジェットを選択した状態で:

- **作成時に取り込み**（デフォルト、[設定可能](./editor-settings)）: 新しいウィジェットのターゲットリストには、
  追加した時点で選択されているコントロール/アクターがあらかじめ設定されます。ビューポートで選択 →
  Add Widget、これだけで作成は完了です。
- 属性エディタのターゲット欄には、解決済みの読みやすい概要（GUID ではなく実際のアクター名と
  コントロール名）が表示されるため、接続を一目で確認できます。壊れた参照
  （削除されたアクター、名前が変更されたコントロール）は、ページをエラーにするのではなく、単に何にも解決されません。

## 2 つの選択の考え方 \{#two-selection-philosophies}

[選択ボタン](./widget-select-button) は、ピッカーの 2 つの定番の動作を両方サポートしています。
**選択セット**（クリックで選択を保存済みのセットに置き換える）と **インタラクティブ選択モード**
（ボタンが常にエディタの選択を反映し、クリックで選択に追加する。詳しい動作は選択ボタンのページを参照）です。
選択の収集は意図的にリグに依存しない設計になっています。取り込みとインタラクティブな照合では、
ドロップダウンの現在のリグに属するコントロールだけでなく、エディタでの実際の選択全体が考慮されます。
